# Wild Sketch — 6-day execution plan

## 1. Goal
Build the landing page from the provided design using a clean, reviewable structure and keep the process consistent with team-project rules even when working solo.

## 2. Branch strategy
- main — final stable version
- dev — working branch for integration
- feature/header
- feature/hero
- feature/gallery
- feature/event
- feature/team
- feature/testimonials
- feature/contact
- feature/footer
- fix/responsive
- fix/review

## 3. Task board columns
- Backlog
- To Do
- In Progress
- Review
- Done

## 4. Day-by-day plan

### Day 1 — Planning and setup
- create repo
- create GitHub Projects board
- split the design into blocks
- define section ownership
- create base HTML structure
- create base CSS variables and layout rules
- create README with project notes

### Day 2 — Header and hero
- build navbar
- build hero content block
- add CTA buttons
- add stats section
- check on desktop layout

### Day 3 — Gallery and event
- create gallery grid
- add placeholder images/blocks
- implement event section
- adjust spacing and typography
- check the layout rhythm

### Day 4 — Team and testimonials
- create team cards
- implement testimonial block
- confirm design consistency
- refine colors and shadows

### Day 5 — Contact and footer
- build contact form
- create footer navigation
- add social links
- do final visual corrections

### Day 6 — QA and presentation
- review responsive behavior
- check forms, buttons, links
- fix spacing issues
- deploy to GitHub Pages
- prepare final demo description

## 5. Daily check-in structure
Use the same logic as a team stand-up:
- What I did yesterday
- What I am doing today
- What is blocked or needs review

## 6. Quality checklist
- semantic HTML
- consistent spacing system
- readable text hierarchy
- clear button states
- mobile-friendly layout
- functioning links
- clean repository history

## 7. Delivery rules
- no work directly in main before review
- each section should be merged via a PR
- every section must be checked visually before moving on
- final version must be clean and stable before demo
